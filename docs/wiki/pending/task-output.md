# Follow actual task output

The worker returns task-specific output through `GET /tasks/:id/output?after=0&limit=100`. The existing mutual TLS boundary authenticates every read. The controller proxies the response only for the selected task and does not copy it to fleet-wide events, audit history or the database. Authentication links, codes, provider messages, raw JSON-RPC envelopes, raw reasoning, approval bodies and unrelated process notifications are not part of this stream.

## Follow and resume

The response contains `taskId`, `events`, `nextCursor`, `oldestSequence`, `latestSequence`, `gap`, `truncated` and optional `resetReason`. Events have a monotonically increasing `sequence`, `kind`, `content`, UTC `at`, optional `itemId` and `stream`, plus `truncated` and `redacted` flags. Request the next page using the returned `nextCursor`, not a locally estimated value. `limit` must be between 1 and 200 and `after` must be a nonnegative integer. A page with `truncated: true` has additional retained events to read. An event with that flag indicates omitted event content instead.

`gap: true` means the requested cursor cannot reconstruct all earlier output. The response never invents missing entries. `oldestSequence` identifies the earliest retained event. A cursor ahead of this worker receives `cursor-ahead-of-worker`. Output itself is memory-only; only the last sequence number is durable. After restart, new sequences continue above that number and `worker-restarted` explains the unavailable earlier text. At most 32 task buffers remain resident, preserving the active task; reading an evicted task reports `worker-buffer-evicted` and its saved cursor. Retained event JSON is bounded to 256 KiB and 512 events per task, whichever is reached first.

## Read the event kinds

| Kind | Actual source |
| --- | --- |
| `assistant` | `item/agentMessage/delta`, with a completed-message fallback when no deltas arrived |
| `command` | The command from a `commandExecution` item when it starts |
| `command-output` | Ordered `item/commandExecution/outputDelta` text, with a completed aggregate fallback when no deltas arrived |
| `file-change` | Actual file paths and operation kinds from file-change items and patch updates; diff bodies are excluded |
| `progress` | Reported plan steps, normalized error/retry status and unsupported-permission notices |
| `state` | Worker task state transitions |
| `result` | Actual completed command status/exit code and completed turn status |

Command output is labeled `stream: "combined"`. The task notification combines stdout and stderr; this worker never fabricates separate stream labels. Unsupported permission approval requests remain unsupported and are not accepted. A known request status can be shown without copying its raw error body.

## Privacy and bounds

Text waits for a complete line or item completion before exposure so known credential patterns split across deltas are checked together. Partial lines are bounded to 8,192 characters; longer lines produce an explicit omission marker. Returned event content is at most 2,048 characters. ANSI/control sequences are removed. Known bearer values, credential assignments, private-key headers, credential-bearing URLs, one-time-code shapes and protected authentication/personal-wording contexts are withheld. Recognized protected commands suppress their subsequent item output. This is conservative best-effort filtering: it can hide benign lookalikes, and arbitrary sensitive text cannot be guaranteed detectable. It never replaces source access controls or authorization. No raw transcript content is written to disk or logs.

## Protocol evidence and verification

The mappings were reviewed against [the official app-server documentation](https://developers.openai.com/codex/app-server/) and JSON schemas generated by the installed `codex-cli 0.149.0` using `codex app-server generate-json-schema`. Tests use the documented fields for assistant deltas, command lifecycle/output, file changes and plan updates. The generated full schemas are ignored local verification output, not a second bundled protocol definition.

`dotnet run --project worker/tests/Worker.Checks.csproj` covers actual text projection, combined stream fidelity, aggregate deduplication, progress, excluded notifications, split-pattern redaction, protected wording output, replay gaps, cursor paging, restart continuity and long-line omissions. These fixtures do not claim a live authenticated model turn. That final runtime check requires an enrolled worker with verified account login.
