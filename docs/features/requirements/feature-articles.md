# One detailed article per feature on the GitHub Pages

The documentation lives on the GitHub Pages, not only in the repository: every feature has its own detailed article covering behaviour, configuration, error modes, security, and verification, ending with suggested articles so no reader hits a dead end. Articles and the GitHub Pages itself are updated in the same project-changing task that changes the behaviour, and long pages use navigable sections rather than one long scroll.

## Applicability

Applicable product surfaces must implement this behavior individually. A feature on one surface does not establish delivery on another.

## Current delivery state

Unfinished. No complete implementation or runtime acceptance is claimed. Review the delivery inventory for evidence as work lands.

## Acceptance

Verify the real behavior, localization, accessibility, persistence and reset where state exists, failure and recovery paths, and genuine built-surface evidence. Source presence alone is insufficient.
