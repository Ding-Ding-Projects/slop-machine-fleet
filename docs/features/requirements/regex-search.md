# Regex builder on every search surface

Every project includes a complete RegexBuddy-parity workbench covering every documented feature, including construction, replacement syntax, analysis, flavor/version comparison and conversion, testing, tracing, benchmarking, code/templates/escaping, parameterized collections, safe GREP, history, integration and preferences. Each product maintains a dated, hand-written per-topic parity ledger with official sources, implementation, exact engine/version bindings and built evidence, reviewed against the complete manual on adoption and builder changes; unavailable capabilities remain explicitly unfinished. Every searchable surface and dropdown has its own adjacent anchored full builder with independent query, pattern, flags, validation, mode, history and snippets, plain text by default. Execution stays local, bounded and time-limited, with a hand-written per-surface search inventory and the complete parity procedure governing proof.
- **Applies to:** application · GitHub Pages · browser extension · repository (a runnable builder for an repository with no UI)
- **Contract:** ui-contract.md § Regex builder
- **Proof the contract demands:** universal proof; a complete dated per-topic RegexBuddy parity ledger and update review; actual engine/version-bound construction, analysis, compare/convert, testing, debug, benchmark, reuse, GREP and integration workflows with honest open capability gaps; valid, invalid, no-match, Unicode, encoding, multiline, zero-width, capture-group, and adversarial cases on the real engine; verified replacement preview, cancellation and backup restoration; the full builder exercised from every search surface; guards that turn red when one required parity topic, implementation/evidence binding, surface, field, builder registration, or isolated-state binding is removed.
- **Related:** command-palette, context-menus, tabs, collapse-filters
