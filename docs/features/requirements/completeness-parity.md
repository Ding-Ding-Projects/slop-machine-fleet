# Per-surface completeness inventory and parity

Every user-facing application and GitHub Pages implements every canonical feature independently, with no delegation to a sibling, a shared GitHub Pages, a future release, a hidden route, or a placeholder. Each project keeps a hand-written per-surface completeness inventory naming every canonical feature with links to implementation, documentation article, localized copy, persistence, focused gate, built-artifact interaction proof, and real screenshot evidence, and a project-changing task fails closed on any absent, stale, or unproven row. An executable negative-regression gate removes one asserted item at a time with exact boundaries and must turn red, then green, and release-grade shutdown adds the hand-written deep audit and the per-click screenshot ledger.

## Applicability

Applicable product surfaces must implement this behavior individually. A feature on one surface does not establish delivery on another.

## Current delivery state

Unfinished. No complete implementation or runtime acceptance is claimed. Review the delivery inventory for evidence as work lands.

## Acceptance

Verify the real behavior, localization, accessibility, persistence and reset where state exists, failure and recovery paths, and genuine built-surface evidence. Source presence alone is insufficient.
