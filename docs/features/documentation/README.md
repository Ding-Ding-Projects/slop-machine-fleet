# Read the documentation interactively

The public documentation companion explains Slop Machine Fleet. It is not the controller, does not provision workers and never accepts cloud credentials. Start with a guided journey, choose a step and read its linked full article. Checklist changes are visitor-owned reading progress, not proof that an installed application executed anything.

## Complete articles and navigation

Build preparation inventories the root README and every Markdown file below `docs/`, including prepared wiki pages. Every article is bundled in full with its source path and SHA-256. Human-readable task categories lead navigation; source links remain optional provenance. Internal article links and heading anchors stay inside the reader. Unknown articles and unavailable assets remain explicitly unavailable.

The renderer uses a Markdown parser and escaped React elements for headings, paragraphs, lists, tables, code, links and images. Raw HTML is displayed literally, never executed. Only local bundled images are embedded. External HTTPS links are explicit navigation; embedded remote assets, unsafe protocols and traversal outside the project are rejected.

## Search and preferences

The prominent documentation search stays available on home, category, article and settings routes. Its adjacent regex workbench shares state with the owning search and executes patterns in a worker with a bounded timeout. It declares unsupported engine conversion, step tracing and full RegexBuddy parity honestly.

Language, theme and reduced-motion settings persist under a documentation-only local key. English, Cantonese and bilingual modes translate navigation and guided explanations. Complete source articles retain their original language, with this limitation visible in the reader. The public documentation has no personal-wording importer, no authentication storage access and no controller API calls.

## Downloads and release evidence

Without `apps/docs/release.json`, the companion shows downloads as unavailable. The parent release workflow must provide externally verified normal-release evidence, exact source commit and asset names, sizes, SHA-256 hashes and immutable download URLs. The build validates the configuration shape and project URL boundary; this validation does not independently verify publication.

## Local development and deployment

The `@fleet/docs` workspace prepares content before its build. The root build entrypoint owns production invocation. Static output uses `/slop-machine-fleet/` as its base. Original design tokens and fonts are read from the pinned original design commit during preparation, without tracking duplicate imported reference files. Assets are local and do not require a CDN.

Hosting, the repository homepage, actual live navigation, asset delivery and browser persistence must be verified separately after deployment. Prepared wiki pages are not evidence that the forge wiki has been published.

## Remaining acceptance

The complete settings inventory, full regex parity, all required feature equivalents, native onboarding, packaged companion, translated full articles and built/deployed layout matrix remain unfinished. A successful source compilation or content inventory is not runtime acceptance.
