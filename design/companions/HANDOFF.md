# Fleet companion interaction contract

Three independently packaged portable Windows tools share local typography, spacing, theme and language controls. The secure productive client remains separate. No remote fonts, renderer Node access, embedded credentials or arbitrary shell command forms are permitted.

## Build workspace

The header identifies Fleet Build and the selected source folder. A native folder picker validates the Fleet package identity and exact root entrypoints. Three clear actions invoke Build, Build and run, and Build installer. The progress region shows bounded, redacted output and actual child exit status. One operation runs at a time. Cancel ends only the owned process tree and explicitly does not roll back completed filesystem changes. Interrupted state is restored as incomplete on restart. Starting requires an explicit click after source selection.

## Hosting setup

Four persistent steps: select the Fleet source folder; check Docker engine and Compose; configure a LAN hostname, HTTPS port and immutable published image reference; review and start using host.bat --detached. Existing configuration is loaded for review, never silently overwritten. The storage choice is the existing named Compose volumes, with their exact names explained; moving existing data is unavailable. Setup credentials remain in the host entrypoint's ACL-protected .local files and are never displayed. Success requires the entrypoint's verified HTTPS LAN result. Certificate trust failures remain incomplete. Back preserves drafts, cancellation preserves running containers and completed setup effects.

## Offline reading

Task-led entry cards lead to build, hosting and account setup articles. A searchable article list and complete article reader support local Markdown headings, lists, links and code. Internal paths resolve only to bundled article inventory entries. All root documentation and wiki Markdown, plus root README, ROADMAP and HANDOFF, are indexed at packaging time. Missing documentation fails packaging. External links are labelled and disabled offline. Source code fences are rendered as text.

## Shared behavior and verification

Normal viewport 1100 x 780, minimum 640 x 520. Navigation wraps on narrow screens; content scrolls rather than truncates. Keyboard focus rings, semantic headings, labelled inputs, polite progress announcements, accessible errors and reduced-motion support apply. English, Cantonese and bilingual UI controls persist locally with light/dark/system theme. Main actions use translated labels; source articles retain their own language.

State identifiers: build.empty, build.ready, build.running, build.cancelled, build.failed, build.complete; host.source, host.checking, host.configure, host.review, host.running, host.incomplete, host.verified; docs.index, docs.article, docs.empty-search.

Runtime acceptance remains pending until built portable files are driven. Full universal settings and RegexBuddy parity, exhaustive contextual guidance/playgrounds, personal wording import, sound effects, reference-image parity and complete scale/language matrix are unfinished and must not be represented as delivered by this compact implementation. No generated design image is runtime evidence.

## Independent review conditions

The separate design review approved bounded implementation. Build actions use exactly `build.bat /s`, `build.bat /s /run` and `build-installer.bat /s`. Selected source needs an explicit trust checkbox because its scripts execute with the current user's permissions. IPC carries action enums and bounded structured fields only. Cancellation retains owned child identity and never stops the container engine or running containers. Existing protected-file ACL verification and usable first-owner authorization remain owned by the hosting entrypoint, not by renderer code.

The packager includes nested documentation/wiki Markdown, deployment articles, the root documentation records and local Markdown image references as bundled image data. Unsafe/outside-source assets fail packaging, external links remain inert references, and internal headings and article links remain navigable. The reader uses DOM text nodes and restricted local link resolution, never HTML injection. Raw HTML, complex Markdown extensions, arbitrary attachments and remote image download are not implemented and remain visible as source text or inert references.
